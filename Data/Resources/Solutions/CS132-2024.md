>[!hint]- Hint 1

>[!hint]- Hint 2
> What happens when a carry from a previous bit position is needed?

>[!check]- Solution
> A half adder adds two binary inputs and produces a sum bit and a carry bit.
>
> A full adder adds two binary inputs and an additional carry-in bit from a previous stage, producing a sum bit and a carry-out bit.
>
> Therefore, a full adder can be chained to perform multi-bit addition, whereas a half adder cannot directly handle an incoming carry.

**ii.** How can the full adder be extended to allow the addition and subtraction of two binary numbers? Provide a circuit diagram and a name for this.

>[!hint]- Hint 1
> Recall how subtraction can be performed using two's complement.

>[!hint]- Hint 2
> XOR gates can be used to conditionally invert bits.

>[!check]- Solution
> The second operand $B$ is passed through XOR gates controlled by a signal $S$.
>
> When $S=0$, the XOR gates leave $B$ unchanged and the circuit performs:
>
> $$A + B$$
>
> When $S=1$, the XOR gates invert every bit of $B$ and a carry-in of $1$ is supplied to the least significant full adder:
>
> $$A + \overline{B} + 1$$
>
> which is equivalent to:
>
> $$A - B$$
>
> This produces a circuit capable of both addition and subtraction.

```text
      S
      |
B ----XOR----\
              \
A ------------> Full Adder ---> Sum
              /
Carry In = S /
```

**iv.** How could Equation 1 be improved using Boolean Logic? Provide the result of this operation(s).

>[!hint]- Hint 1
> Use the XOR identity:
>
> $$
> X \oplus Y = X\overline{Y} + \overline{X}Y
> $$

>[!hint]- Hint 2
> Here, $X = A\overline{B}$ and $Y = \overline{C}+D$.

>[!check]- Solution
> Let:
>
> $$
> X = A\overline{B}, \qquad Y = \overline{C}+D
> $$
>
> Using:
>
> $$
> X \oplus Y = X\overline{Y} + \overline{X}Y
> $$
>
> we get:
>
> $$
> (A\overline{B})\overline{(\overline{C}+D)} + \overline{(A\overline{B})}(\overline{C}+D)

>

>
> $$
> \overline{(\overline{C}+D)} = C\overline{D}

> $$

>
> This is an improved Boolean expression because it removes the XOR and expresses the circuit using AND, OR and NOT gates.

**(b)** A hardware engineer is looking at building a processor.

**i.** What is the difference between computational logic and sequential logic?

>[!hint]- Hint 1
> Think about whether the output depends only on the current input or also on previous values.

>[!check]- Solution
> Computational logic, also called combinational logic, produces outputs that depend only on the current inputs.
>
> Sequential logic produces outputs that depend on both the current inputs and stored previous state.
>
> Therefore, sequential logic requires memory elements such as flip-flops or registers, while computational logic does not.

---

**ii.** What is a decoder, and which category does it fit in?

>[!hint]- Hint 1
> A decoder takes a compact binary input and activates one of several outputs.

>[!check]- Solution
> A decoder is a digital logic circuit that takes an $n$-bit binary input and activates one of $2^n$ possible outputs.
>
> For example, a 2-to-4 decoder has 2 input bits and 4 outputs. Each input combination selects exactly one output.
>
> A decoder fits into **computational/combinational logic** because its output depends only on its current input and it does not store state.

---

**iii.** What is a counter, and which category does it fit in?

>[!hint]- Hint 1
> A counter needs to remember its previous value.

>[!check]- Solution
> A counter is a circuit that stores a value and changes that value in response to clock pulses.
>
> For example, a binary counter may count:
>
> $$
> 00,\ 01,\ 10,\ 11
> $$
>
> before wrapping around.
>
> A counter fits into **sequential logic** because it must remember its previous state in order to produce the next value.

---

**iv.** What is the difference between active high and active low components, and why should the version be picked carefully?

>[!hint]- Hint 1
> Think about whether a signal is triggered by logic 1 or logic 0.

>[!check]- Solution
> An active high component is enabled when its control signal is logic $1$.
>
> An active low component is enabled when its control signal is logic $0$.
>
> These should be chosen carefully because using the wrong version may cause a component to activate at the wrong time. This can lead to incorrect data movement, incorrect control signals, or unintended writes in a processor.
>
> Active low signals are often written with a bar, for example $\overline{EN}$, to show that the signal is enabled when low.

**(a)** When designing a processor, the way in which the memory is structured is incredibly important to the performance of the processor.

**i.** What is the memory hierarchy?

>[!hint]- Hint 1
> Think about the different types of memory between the CPU and long-term storage.

>[!hint]- Hint 2
> As you move away from the CPU, memory generally becomes larger, cheaper, and slower.

>[!check]- Solution
> The memory hierarchy is the arrangement of memory technologies according to their speed, cost, and capacity.
>
> A typical memory hierarchy is:
>
> ```text
> Registers
> ↓
> L1 Cache
> ↓
> L2 Cache
> ↓
> L3 Cache
> ↓
> Main Memory (RAM)
> ↓

> ↓
> Archival Storage
> ```
>
> Registers are the fastest and smallest form of memory, while secondary and archival storage are much larger but significantly slower.
>
> As we move down the hierarchy:
>
> - Capacity increases
> - Cost per bit decreases
> - Access time increases
>
> The hierarchy allows a processor to achieve high performance while still providing large amounts of storage.

---

**ii.** Why is the memory hierarchy important?

>[!hint]- Hint 1
> Consider the difference in speed between a CPU and main memory.

>[!check]- Solution
> The memory hierarchy reduces the average memory access time by keeping frequently used data in faster memory levels such as caches and registers.
>
> Without a memory hierarchy, the processor would frequently stall while waiting for slower memory accesses, significantly reducing performance.

**(b)** The company only needs to send data from the sensor when the readings have changed, in order to save power. Name a synchronous I/O technique that could aid in this. How does this technique work?

>[!hint]- Hint 1
> What happens when a device needs attention only occasionally?

>[!hint]- Hint 2
> The processor should not continuously poll the sensor.

>[!check]- Solution
> A suitable technique is **interrupt-driven I/O**.
>
> In interrupt-driven I/O, the processor continues executing other instructions while the sensor operates independently.
>
> When the sensor detects that its reading has changed, it generates an interrupt signal.
>
> The processor:
>
> 1. Completes its current instruction.
> 2. Saves its current state.
> 3. Jumps to an Interrupt Service Routine (ISR).

> 5. Restores its previous state and resumes execution.
>
> Because the processor only communicates with the sensor when required, power consumption is reduced compared to continuous polling.

**ii.** Why would the startup company want to use a DMAC over other methods of I/O?

>[!check]- Solution
> DMA is often preferred because it significantly reduces CPU overhead during large transfers.
>

>

**iii.** How does a DMA transfer data from an I/O device to memory?

>[!hint]- Hint 1
> Think about the sequence of events from requesting a transfer to completing it.

>[!hint]- Hint 2
> The DMAC temporarily gains control of the system bus.

>[!check]- Solution
> A DMA transfer typically occurs as follows:
>
> 1. The CPU configures the DMAC by supplying:
>    - The source device address.
>    - The destination memory address.
>    - The amount of data to transfer.
>
> 2. The I/O device signals that data is ready.
>
> 3. The DMAC requests control of the system bus.
>
> 4. The CPU grants control of the bus and temporarily relinquishes access.
>
> 5. The DMAC transfers data directly from the I/O device to main memory.
>
> 6. The DMAC updates the memory address and transfer count after each transfer.
>
> 7. When all data has been transferred, the DMAC releases the bus.
>
> 8. The DMAC generates an interrupt to inform the CPU that the transfer has completed.
>
> A simplified diagram is:
>
> ```text
>          Configure DMA
> CPU ------------------> DMAC
>  ^                       |
>  |                       |
>  | Completion Interrupt  |
>  |                       v
> Memory <------------> DMAC <------------> I/O Device
>         Direct Data Transfer
> ```
>
> The key feature is that the data moves directly between the I/O device and memory without passing through CPU registers.

> - One register may place data on the bus at a time.
> - Registers are selected using decoder logic.
> - Instructions are executed in a maximum of 6 micro-steps.

>
> $$
> C = \text{Carry}, \qquad N = \text{Negative}
> $$
>

>
> ```text
>                ┌─────────────┐
>                │ Instruction │
>                │  Register   │

>                       │ Opcode
>                       ▼

>                       │
>                       ▼

>                │ Random      │
>                │ Logic       │
>                └──────┬──────┘
>                       │
>         ┌─────────────┼─────────────┐
>         ▼             ▼             ▼
>    Register      ALU Control    Memory
>    Control       (3 lines)      Control
>                                   │
>                                   ▼
>                                  MAR
> ```
>

>

>
> ```text

>         ▼

> ```
>

>

>
> ```text

> ```
>
> allowing up to six micro-instructions per instruction.
>
> Control signals are generated from:
>
> ```text
> Opcode + Timing State + CCR
> ```
>
> using combinational logic.
>

>
> The ALU receives:
>
> - Data from the selected register.
> - Immediate operands.
> - Three function lines.
>
> Example:
>
> ```text

> 001 -> SUB
> 010 -> AND
> ...
> ```
>
> The ALU result is stored in the ALU register and updates the CCR.
>
> ### Branch Instructions
>
> The CCR supplies:
>
> ```text
> C (Carry)
> N (Negative)
> ```
>
> to the control logic.
>
> The random logic enables loading the PC when branch conditions are satisfied.

>
> | Opcode | Mnemonic |
> |---------|----------|

>
> RTL:
>
> $$
> [A0] \leftarrow \overline{[A0]}
> $$
>
> Justification:
>
> NOT allows direct bit inversion.
>
> This simplifies many logical operations and enables efficient construction of XOR and other Boolean functions.

> ### Instruction 3
>
> | Opcode | Mnemonic |

>

>
> $$
> [A0] \leftarrow M[loc]
> $$
>

>
